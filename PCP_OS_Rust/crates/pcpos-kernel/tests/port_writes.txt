# Rust port-writing calls matched by tests/port_writes.py, grouped by file, function and port expression:
# file | function | port as written | when it runs.
# A new write must be read by a person and added here with when it runs before the check passes.
# UNGUARDED marks a write made on hardware before the kernel knows what is at the port: each is a known
# open item, not an approval.
# Assembly reviewed separately: boot.s:unsupported writes its message to COM1 if long mode or NX is
# unavailable. The boot.s user-mode port test attempts a COM1 write and is expected to fault.
# Virtio shared queues require exactly one matching legacy virtio-net PCI function, a valid I/O BAR
# and bus mastering initially off. Callers are explicit boot fixtures (main.rs) or a guest-ethernet
# program admitted by ethernet_grant. Guest access requires a single matching net_image on the exact
# command line and no grant=none. These optional features are absent from the default build.
# For game-link, a matching link_image and a non-console-only launch select the COM2 initialization
# probe. Its scratch-register write precedes readback. Only a successful readback enables configuration.

# Device writes that are not port writes, which this check does not find and a person must look for
# (searched by hand on 21 November 2026 for issue 309: write_volatile, wrmsr, bus_write):
#   arch.rs device_write32, device_fill32: a display's memory, inside the exact bytes mapped for it;
#   arch.rs syscall and thread-pointer setup: five model-specific registers of the processor (wrmsr);
#   dev.rs bus_write: one configuration register (command) of an AC'97 device found by its identity.
# None of them, and no port write in the default build, reaches storage, firmware variables, the
# clock's memory or flash; the default build has no storage or network driver.

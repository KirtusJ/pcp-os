# Build a tester CD from source

The published `PCP-OS.iso` cannot be traced to a commit of this repository, and nothing here built a CD from source ([issue 288](https://github.com/KirtusJ/pcp-os/issues/288)). This directory is that missing recipe. It makes a BIOS optical image from the checked-out source and writes down what went into it. It publishes nothing: whether an image made this way is given to testers is a separate decision.

## What is on the CD and where each part comes from

| File | Source |
| --- | --- |
| `kernel.elf32` | `PCP_OS_Rust/crates/pcpos-kernel`, built by its own `run.sh build` with default features. Guest Ethernet is not compiled in. |
| `surf.elf` | `apps/surfbird/guest`, built with `--features local-media` |
| `clip.ppm`, `clip.wav` | generated by `apps/surfbird/guest/replay_local_media.py` (`make_media`, variant 0); the same bytes as on the published CD |
| `limine-bios.sys`, `limine-bios-cd.bin`, `limine.txt` | the Limine 10.8.5 binary release at commit `7a9013f305de0bea1f6310e76e7baba30499fef0`, each checked by SHA-256. This is the release whose BIOS path does not write to an attached disk ([disk check](../optical-disk-check/README.md)). |
| `limine.conf` | written by the builder; it names the measurement of the kernel that was just built |
| `notices.txt` | every external crate compiled into the two programs, with the license files each crate ships |
| `notice.md`, `readme.txt` | the workspace notice, and a short text naming the source commit and the measurement |

## Build

Linux, with Rust 1.97.0 including its source and the `x86_64-unknown-none` target, `ld.lld`, `objcopy`, `xorriso` and Python 3, and a checkout of the pinned Limine release:

```sh
rustup toolchain install 1.97.0 --profile minimal -c rust-src -t x86_64-unknown-none
git clone https://github.com/Limine-Bootloader/Limine limine
git -C limine checkout 7a9013f305de0bea1f6310e76e7baba30499fef0
python3 examples/tester-cd/build.py limine out
```

`out/pcp-os-tester.iso` is the image and `out/receipt.json` records the source commit, whether the checkout had uncommitted changes, the compiler, the features, the kernel's measurement, and the size and SHA-256 of the image and of every file on it.

The image is assembled twice and the two must be equal. Both programs are compiled in one fixed folder (`/tmp/pcpos-tester-cd-build`, or `PCPOS_TESTER_CD_STAGE`), because the folder a crate is compiled in is part of what the compiler produces. With that, two builds of one commit into differently named output directories gave the same image on one machine. The folder the Rust toolchain is installed in still enters the kernel's measurement, so another machine can give another measurement and another image digest from the same commit. Compare receipts, and treat the digest of an image as belonging to the machine that built it until that is removed.

## Check

```sh
python3 examples/tester-cd/check.py out evidence
```

It boots the image with nothing but the CD attached on QEMU's `pc` and `q35` machines, each on the ordinary clock and on the instruction-counted one. In each of the four sessions the kernel must measure as the receipt says, pass every startup self-test, play the demo to `DONE`, stop a second launch with the kernel's Stop key, show the register and power off on request. It fails if the kernel reports that guest Ethernet is compiled in. Run against the published CD it fails for that reason in all four sessions, which is the control for that assertion.

## First result

At `e13fdd20d78d20f710e9d077ae76c8e8fc685656`, on Linux x86_64 with QEMU 8.2.2 (TCG): kernel measurement `103f476e9532f85017ea5839f4444f73085465ce36f3d22c6e4372202148565a`, image 2,498,560 bytes, SHA-256 `1cfc6da85752edf8e347566357f746a9e9fe08c69fb382dd93d25c55d4248d0e`, the same from two output directories. All four sessions passed with 71 startup checks each.

## What this does not show

One emulator on one host. No physical machine, no UEFI firmware (see [issue 281](https://github.com/KirtusJ/pcp-os/issues/281)), no other hypervisor, no attached disk (the [disk check](../optical-disk-check/README.md) covers the loader), and no storage that outlasts power, which the kernel does not have. The license files in `notices.txt` are the ones each crate publishes; whether that meets every license's terms for a distributed image has not been reviewed.

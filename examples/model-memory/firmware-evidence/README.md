# Multiboot model handoff from OVMF to a native companion

These are the measured inputs and console captures from Director B3's full-size synthetic trial for PCP OS #371 and #375. The QEMU guest used 8 GiB RAM. Firmware read 75 ordinary FAT32 shard files, passed two typed physical extents and a separate low manifest to the kernel, then transferred control. The companion opened the model device, checked its descriptor and manifest against its compiled reference, mapped the payload read-only, and compared all 5,027,783,488 model bytes with the expected pattern. The foreground process waited for the companion's acknowledgement and end of file. The receipt names the emulated boot media and gives measurements for each run.

The four text capture pairs contain the guest's EFI debug port and serial port output. The kernel register head and timing may vary between cold boots. The ISO was mastered with the exact #375 build.py from commit 1187f135481ee6820ffa1942580cc8699fa112b5. The geometry receipt records an independent full byte comparison of the EFI partition against the input FAT.

The source captures include the experimental EFI loader, its build headers, the separate pinned model.manifest and the guest reader. The reader's build with no features is the foreground process. The reader feature builds its paired companion. Both use the repository's native guest library and flux-rink guest linker script. The firmware uses examples/firmware-owned-uefi/handoff.S. The kernel source is commit 16806df35ddbf8963a0907684df786abc77cdb53 with the repository’s firmware-owned-uefi 32 MiB relocation applied against this head (resulting git diff SHA-256 eb8215fa7cb0143f7361c3cf1806f825227f6e616e86808b3006ca0475f4f73e), built with proposals and model-memory. The release-ineligible model-memory-fixture feature is off. The experiment uses synthetic bytes throughout and covers emulation only.

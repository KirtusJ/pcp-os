# Native Qwen2 and Qwen3 fixture forward passes

Director B3 tested the four reference token positions from PCP OS #378 in the companion process of the #371 kernel. Each fixture was an ordinary GGUF on a 96 MiB FAT32 volume. An EFI loader passed two physical extents separated by a page and the low manifest to the kernel. The same native companion ELF served both fixtures. It opened the model device, matched the trusted manifest pin, verified the read-only mapping with VerifiedSlices, and passed its borrowed bytes to the GGUF index, Qwen admission and forward decoder.

The two serial captures contain the four 16-logit rows as f32 bit patterns, followed by the cancellation and retry result. The receipt includes the bit patterns, input and executable identities and maximum error against the pinned reference for each family. For each position, compare every logit against the corresponding checked-in reference value with absolute tolerance 2e-5 plus 2e-5 times the absolute reference value.

Each guest also reset the decoder and repeated the same four tokens. On the third token it cancelled at the penultimate callback measured during the uninterrupted run. The position stayed at two. Retrying that token and continuing through token four reproduced every output bit from the first run. The finite, two-layer F32 fixtures used the repository’s fixture generator. Real model weights, tokenization, sampling, text generation, optimized quantized numerical parity, and physical hardware remain outside this measurement.

The source directory contains the measured guest and EFI loader inputs. The EFI loader uses the existing firmware-owned-uefi/handoff.S. Family-specific headers set the independently generated manifest pin. The guest uses the repository’s native guest library, its page allocator from parrots-all-the-way-down, pcpos-model-media, pcpos-gguf, pcpos-qwen and the checksummed libm version in the receipt. The kernel uses the same 32 MiB link relocation as B3’s full-size firmware handoff.

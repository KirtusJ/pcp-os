## Proposed product contract, not a PCP method amendment

1. **Actual bus enumeration:** the trusted OS supplies current device handle, PCI path/function, controller/reset epoch, device generation and UEFI `MediaId` when that firmware Block I/O path is active, capacity in 512-byte protocol sectors, a separately validated GPT LBA size, read-only/flush capability and present/in-flight state. A controller path, GPT Disk GUID, static marker or virtio ID is *not* authenticated physical drive identity. For the legacy virtio configuration without generation field, follow Virtio's consistent configuration-read requirement, and separately audit change/reset handling.
2. **Selection versus effect authority:** a written principal instruction identifies current target, contents, operation, region and selected image digest. The **host** captures authentic actor/authorization and binds it to the enumerated handle/generation/epoch, exact scope, expiry/revocation, transaction and destination. The model, the interface, a checkbox, a `store_id=` token, an on-media marker, UEFI MediaId or a procedural override can never grant a disk write. Re-check authority at the destination before irreversible effects.
3. **Typed geometry:** keep firmware optical 2048-byte records, virtio protocol 512-byte sectors, and GPT logical LBAs as separate units. Check arithmetic overflow, capacity changes and partition boundaries. On fresh whole-disk factory copying require the target's exact capacity to match the factory image; a larger target needs separately proved GPT backup relocation/expansion. No silent partial image copy.
4. **Media condition:** a fully blank claim requires an actual full-media check or an explicitly weaker label. A valid GPT is *populated*, not blank. Corrupt/contradictory primary or backup GPT, stale backup after resize, unknown contents, truncated image, mismatched digest or unverifiable volume identity are not automatic permission to erase. Validate primary+backup GPT headers, CRCs, arrays, reciprocal locations, partition ranges and nonoverlap; use a separately authorized repair route.
5. **In-flight fencing and durability:** on unplug, controller reset, changed geometry, stale selection, revoked grant or cancellation, do not submit further writes and explicitly observe/drain/fence outstanding requests before returning completion or reusing DMA memory. Distinguish completed, possible and unknown effects. Do not label installation durable without supported successful flush and independently observed readback. Checkpoint and cancel behavior after a power cut requires a new approval.
6. **Recovery:** independently accessible recovery with the installed disk absent, both GPT copies damaged, keys unavailable, both system slots invalid and update interruption at each stage must have named outcomes. Physical-device testing remains separate from disposable QEMU fixture evidence. Keep encrypted volume tests independent from plaintext disk identity.
7. **Evidence-source mode:** local source inspected offline, externally inspected material, available-but-unread, and unavailable source must be separately reported. Core §15.8's actual `Grounding/Delivery/Execution/Observability` axes remain governing; this fixture's source labels are **proposed** descriptive metadata, not canonical PCP enum extensions. Optional external research being unavailable does not authorize bypassing high-consequence installer checks.

## Fixture contract

`target_preflight.py` is a *pure model* taking caller-supplied facts; no device, user, permission mechanism, source file, cryptographic signer or OS is accessed. It can return only `HOLD` or **`ELIGIBLE_FOR_HOST_RECHECK`**, never `AUTHORIZED` or `SAFE_TO_WRITE`. A virgin blank disk need not contain a pre-existing **on-media marker**, so the mock plan may match an empty `volume_marker`. This field is separate from the UEFI `EFI_BLOCK_IO_MEDIA.MediaId` **firmware-provided UINT32 media-change token**; the mock `uefi_media_id` captures that reported value and rejects a mismatch, but a same-value token is not disk authentication and may fail to detect an unreported backing-store substitution. This initial restrictive profile holds when there are two writable block devices **even if one is on an unsupported bus**, because unsupported is not invisible. An externally sourced cache that is accessible offline but unread is `NOT_INSPECTED`, not `UNAVAILABLE`. `test_target_preflight.py` exercises expected consistency failures and **preserves an indistinguishability counterexample** where a same-port full clone can pass the pure model. Do not treat a green model test as disk safety.

Run all tests with `python3 -m unittest discover -s os-docs/boot-storage-acceptance -p 'test_*.py' -v` from the repository root. The four additional `uefi_media_id` controls exercise a changed firmware token, invalid token types, and a valid zero-valued firmware token alongside a blank on-media marker.

## Additional sparse GPT metadata checks and write-attempt oracle

`gpt_metadata.py` performs bounded, read-only inspection of **caller-supplied in-memory LBA-to-bytes mappings**. It does not open files, devices, images or any privileged API. This is a deliberately conservative **first-tier profile** supporting 512-byte and 4096-byte GPT logical blocks, revision 1.0, a minimum 16 KiB entry array and a fixture-sized maximum 1 MiB entry array. Unsupported formats are **HELD**, not diagnosed as defective product media.

The separate `test_gpt_metadata.py` builds synthetic sparse metadata (not a disk image) and checks a protective MBR; primary and backup GPT header signatures, sizes, CRC32 and reciprocal locations; partition-entry arrays with independent CRCs and matching content; bounded usable LBAs; and disjoint, uniquely identified partition entries. It exercises valid 512/4096-byte cases, corrupted headers/arrays, stale backup after a capacity change, internally self-consistent but mutually contradictory metadata, duplicate GUIDs and overlap, missing sectors and arithmetic extremes. A full clone of the same metadata **still passes**, as it must: an on-media CRC is not device authentication or operator permission.

Two additional tests demonstrate a separate **oracle limitation**: writing the same bytes, or writing and then restoring the previous contents, can leave final SHA-256 hashes unchanged even though write attempts occurred. Their recorder is entirely simulated in memory. A true product refusal test must independently observe actual driver/backend **write attempts and authorized dispatch bindings**, as well as before/after bytes; neither this model nor the historical public IDE CI is that oracle.

The relevant public standard text is [UEFI 2.11 GPT §5](https://uefi.org/specs/UEFI/2.11/05_GUID_Partition_Table_Format.html), inspected through source-index excerpts because the direct HTML endpoint returned HTTP 403 in this session. The excerpt includes the required 92-byte minimum header, CRC32 field layout, end-of-media alternate GPT, minimum 16,384-byte entry array and nonoverlapping usable partition bounds. [OASIS Virtio 1.3 §5.2](https://docs.oasis-open.org/virtio/virtio/v1.3/virtio-v1.3.html) was directly opened and distinguishes 512-byte request sectors, configuration capacity, read-only capability and flush semantics. These sources **inform** tests; neither certifies the private product. Director PT's later [source `ba48b751...` report](https://github.com/KirtusJ/pcp-os/issues/132#issuecomment-6910139562) remains producer-attributed, not fetched here.

Run all source-only tests with `python3 -m unittest discover -s os-docs/boot-storage-acceptance -p 'test_*.py' -v` from the repository root. The isolated GitHub Actions job runs this exact suite and reports source SHA-256 values.

## Exact-type negative controls (fixture only)

The model now rejects a Python `True` used as an integer epoch/generation, numeric floats supplied where exact integer bytes or logical-block counts are required, string values such as `"false"` masquerading as boolean device flags, non-enumerated media conditions, missing/nonstring digests, malformed plan fields and invalid firmware `MediaId` types. Both GPT total-LBA and logical-block-byte count also require exact integers. This prevents accidental Python equality (`True == 1` and `512.0 == 512`) from becoming apparent acceptance evidence. The tests explicitly construct otherwise matching positive inputs so refusal cannot pass merely because an unrelated field differs.

The complete **source-only suite contains 92 tests**, 53 for proposed device preflight/evidence labels and 39 for GPT byte-metadata consistency and simulated write-attempt oracles. This figure is *fixture count*, not 87 independent real-world installation validations.

## Adversarial source-specification correction: GPT reserved fields and protective-MBR fixture

A source-level check against the indexed [UEFI 2.11 GPT §5 tables](https://uefi.org/specs/UEFI/2.11/05_GUID_Partition_Table_Format.html) identified **three formerly accepted bad synthetic fixtures**. The direct HTML fetch returned HTTP 403, so the precise GPT table requirements were inspected through public indexed text and should be confirmed independently in a release standards audit. These are checker/fixture defects, **not findings about PT's private installer**.

1. **GPT HeaderSize vs reserved bytes:** UEFI's revision-1 header permits `HeaderSize >= 92` with CRC calculated over that count, but separately names offset **92 to BlockSize** as reserved/zero. The previous model checked only `block[HeaderSize:]`, which could accept `HeaderSize=96` plus nonzero bytes 92..95 after recomputing the CRC. It now checks `block[92:]` regardless of HeaderSize. A positive test with size 96 and **zero** reserved bytes remains accepted.
2. **Partition attribute bit mask:** UEFI 2.11 GPT entry attributes **bits 3..47** are reserved/zero; bits 0..2 are defined, 48..63 belong to partition-type-specific ownership. The old model accepted bit 3 set after recalculating both entry-array and header CRCs. It now refuses this mask and retains a positive bit-2 control. This remains a scoped attributes test, not validation of every partition-type-defined high bit.
3. **Protective MBR EndingCHS:** The previous positive fixture supplied `EndingCHS=00 00 00` despite the protective entry covering the disk. The revised synthetic factory calculates a conventional 255-head, 63-sector translation for its last LBA, with `FF FF FF` overflow as an appropriate fixture sentinel. The parser now rejects **all-zero** end-CHS as impossible for a full-disk record. **It does not independently verify the correct end-CHS mapping** because actual CHS geometry is not supplied or authenticated; do not claim full protective-MBR standards conformance.

**Test-first falsification, with failures retained:** [GitHub Actions run 43829004926](https://github.com/KirtusJ/pcp-os/actions/runs/43829004926), exact authored test-only head `d33ae8ebe982fce4f15fa81130635d65abd95646`, ran **92 tests: three targeted negative controls failed**, each printing `METADATA_CONSISTENT_ONLY` on a malformed synthetic layout. After changes only to `gpt_metadata.py`, [PR Actions run 43829159186](https://github.com/KirtusJ/pcp-os/actions/runs/43829159186), authored head `43fce7cba43821dc8452e48b31173bd32545e7fd`, passed **92/92** (including the same controls). The original failing job is evidence of an actual narrower model defect, not a completed implementation. An independent release implementation still needs exact native UEFI Block I/O and GPT ingestion, refusal/repair traces and validation on disposable actual media.
